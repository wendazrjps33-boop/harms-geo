## 4. 阻塞项详情

### BUG-V26-01：采纳检测只执行一次（高）

**问题**：`run_adoption_checks` 内部去重逻辑只检查是否存在同类检查记录，导致每篇内容只检测一次，无法实现"发布后第 3/7/14/30 天"的多次检测。

**影响**：核心功能缺失，无法跟踪采纳效果随时间的变化趋势。

**修复建议**：修改去重逻辑，按 `days_after_publish` 区分多次检测。例如检查是否存在 `check_type="platform_index" AND days_after_publish=7` 的记录。

**关联文件**：`backend/app/services/adoption_verifier.py:147-154`

### BUG-V26-02：配额检查在生成之后执行（高）

**问题**：`POST /api/content/generate` 使用 `require_feature("content_generation")` 检查功能权限，但未使用 `require_quota("content")` 检查用量配额。配额检查发生在 `_run_generation` 之后（`usage_tracker.increment`），而非之前。

**影响**：Free 用户可绕过配额限制，无限生成内容。

**修复建议**：在端点添加 `require_quota("content")` 依赖，在生成前检查配额。

**关联文件**：`backend/app/routers/content.py:37-84`

### BUG-V26-03：平台收录检测直接抓取 Google（高）

**问题**：`check_platform_indexing` 通过 HTTP 抓取 Google 搜索结果页面（`site:url`），违反 Google ToS，生产环境会被 IP 封禁。

**影响**：生产环境不可用，且存在法律风险。

**修复建议**：改用 Google Search Console API、第三方 SEO API（如 Ahrefs、SEMrush），或使用 Bing API 作为替代。

**关联文件**：`backend/app/services/adoption_verifier.py:24`

## 5. 发布建议

**No-Go（不可发布）**

**理由**：

1. **3 项阻塞缺陷**：采纳检测只执行一次、配额检查绕过、Google ToS 违规，均为核心功能缺失或生产环境不可用
2. **配额安全漏洞**：Free 用户可绕过配额限制无限生成内容，直接影响商业模式
3. **采纳检测频率不符需求**：需求明确要求"发布后第 3/7/14/30 天"多次检测，当前只执行一次
4. **平台收录检测不可用**：直接抓取 Google 在生产环境会被封禁，该功能实际上不可用

**修复优先级**：

1. **P0（立即修复）**：BUG-V26-02 配额检查绕过 — 影响商业模式
2. **P0（立即修复）**：BUG-V26-01 采纳检测频率 — 核心功能缺失
3. **P0（立即修复）**：BUG-V26-03 Google ToS 违规 — 生产环境不可用
4. **P1（尽快修复）**：BUG-V26-04~06, V26-09, V26-10, V26-13, V26-14 — 功能缺陷
5. **P2（计划修复）**：BUG-V26-07, V26-08, V26-11, V26-12, V26-15 — 架构优化

**预计修复时间**：3-5 个工作日（3 项 P0 + 8 项 P1）
